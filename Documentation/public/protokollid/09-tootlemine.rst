Revocation and Restoration List
-----------------------------

must be revoked (not counted in the election results) or restored (i.e., a
previous revocation is cancelled and the restored e-vote is counted when

Voting Result
-----------------

Votes decrypted and aggregated by the key application, divided by electoral
districts and polling divisions.

The voting results file must contain the following data for each polling
division:

#. A record showing the number of spoiled and invalid votes. This applies even
   if the polling division had no spoiled or invalid votes: in that case the
   vote count is zero.

#. A record showing the number of votes cast for each choice. This applies
   even if no votes were cast for that choice in the polling division: in that
   case the vote count is zero.

E-Ballot Box
-------------

The file contains votes received by the collection service together with
the associated data for each vote.

The file format is a Zip64 container.

Voter-specific folders are located directly under the root folder `votes`.

File contents:

* :file:`votes/<voter id>/`

 * :file:`<timestamp>.version`

 * :file:`<timestamp>.<vote type>`

 * :file:`<timestamp>.<qualifier>*`

where:

* ``<voter id>`` is the voter's identifier; in Estonia, the personal
  identification code;

* ``<timestamp>`` is the time of vote submission in the format
  ``yyyymmddhhmmssmmm±zzzz``;

  * this timestamp reflects the moment the request was made to the collection
    service and is provided simply to improve human readability of the ballot
    box; the actual time mark or timestamp of the vote is contained within
    one of the qualifying responses;

* ``<vote type>`` is the type of the choices container; in Estonia, BDOC;

  * where BDOC itself is simply a basic profile and does not contain
    qualifying parameters (validity confirmations, time marks, timestamps),

* ``<qualifier>`` is the type of the vote-qualifying protocol, of which the
  currently possible ones are:

   * ``ocsp`` - *Online Certificate Status Protocol* (validity confirmation,
     `RFC 6960 <https://tools.ietf.org/html/rfc6960>`_) confirms the validity
     of the voter's signing certificate at the time of voting,

   * ``tsp`` - *Time-Stamp Protocol* (timestamp, `RFC 3161
     <https://tools.ietf.org/html/rfc3161>`_) confirms that the vote existed
     at the time the request was made,

   * ``tspreg`` - same as ``tsp``, but the nonce is set to the collection
     service's signature on the ``MessageImprint`` element of the request,
     in order to register the vote.

* The files present for each vote are:

 * ``<timestamp>.version`` - the version of the voter list in effect at the
   time the vote was cast;

 * ``<timestamp>.<vote type>`` - the choices container, inside which the
   choice identifier is in the form ``<election id>.<question id>.ballot``.
   In Estonia, the file with the corresponding name inside the BDOC
   container;

 * ``<timestamp>.<qualifier>`` - the response of the vote-qualifying protocol
   request; there may be multiple, but at most one per protocol.


Anonymized E-Ballot Box
----------------------------

Encrypted votes grouped by electoral districts and polling divisions.
The anonymized e-ballot box contains no information about voters.

The anonymized e-ballot box is the output of the processing application and the
input of the key application's decryption tool.
